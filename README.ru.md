# evalstat

[![CI](https://github.com/diskaver-it/evalstat/actions/workflows/ci.yml/badge.svg)](https://github.com/diskaver-it/evalstat/actions/workflows/ci.yml)

*[English version](README.md)*

**Ты поменял промпт, и метрика выросла. evalstat говорит, действительно ли это
произошло — или просто повезло.**

Без аккаунта, без API-ключа, без сети. Читает файл, который твой инструмент для
евалов и так записывает.

```bash
pip install evalstat
evalstat compare results.json
```

```
success on 50 paired test cases

  baseline prompt  0.620
  new prompt       0.680
  difference       +6.0 pp   95% CI [-6.0 pp, +18.0 pp]
  test             McNemar, exact, p = 0.549   (7 gained, 4 lost, 39 tied)

  VERDICT: new prompt is not distinguishable from baseline prompt
```

62% стало 68%. Шесть пунктов — такое обычно мержат. Но посмотри на последние числа
в строке теста: новый промпт **починил 7 кейсов и сломал 4**. Тридцать девять
кейсов не изменились вообще. Сдвинулись одиннадцать, из них семь в нужную сторону —
это такое же свидетельство, как одиннадцать подбрасываний монеты, где выпало семь
орлов.

Проверить на себе за тридцать секунд, без настройки:

```bash
git clone https://github.com/diskaver-it/evalstat && cd evalstat
pip install -e .
python examples/make_demo.py
evalstat compare examples/demo_run.json
```

## Три вопроса, на которые он отвечает

**1. Это изменение реально?**

```bash
evalstat compare results.json
```

**2. Если «не различимо» — сколько кейсов нужно?**

```bash
evalstat plan results.json --detect 0.03
```

```
  the variants disagreed on              11 of 50 pairs (22.0%)
  smallest effect these pairs can see    +18.1 pp
  to see +3.0 pp you need                1 917 paired test cases
```

Пятьдесят кейсов не видят сдвига в три пункта. Они не видят вообще ничего мельче
восемнадцати. Это полезно знать до того, как потратить неделю на подгонку.

**3. Можно ли верить LLM, которая это оценивала?**

```bash
evalstat judge results.json --truth labels.json
```

```
  agreement with the humans  0.900
  shrinkage factor           0.788
  - Differences measured through this judge are shrunk by about 0.79, so an
    observed gap of 5.0 pp corresponds to roughly 6.3 pp of real difference.
```

Оценщик, который иногда ошибается, не просто добавляет шум — он притягивает любую
разницу к нулю. Команда выдаёт этот коэффициент.

## Как гейт

```bash
evalstat compare results.json --fail-on regression
```

Код выхода 1, если кандидат значимо хуже, иначе 0 — пулл-реквест может на этом
падать. Добавь `--anytime`, если метрику проверяют на каждом коммите: повторные
взгляды сами по себе способ обмануться, и этот флаг их учитывает. А
`--format markdown` даёт вердикт, который можно вставить в пулл-реквест.

## Вывод на человеческом языке

| что видно | что это значит |
| --- | --- |
| **paired test cases** | обоим вариантам задавали одни и те же вопросы, поэтому их можно сравнивать по одному, а не двумя средними |
| **pp** | процентные пункты. С 62% до 68% — это +6 pp |
| **95% CI [−6, +18]** | правдоподобный диапазон настоящей разницы. Если в него попадает 0, разницы может не быть вовсе |
| **p = 0.549** | насколько легко случайность сама даёт такой разрыв. Число большое — случайности легко — вывода нет. Обычная планка: ниже 0.05 |
| **7 gained, 4 lost, 39 tied** | кейсы, которые изменение починило, сломало и не задело. Информацию несут только первые два |
| **McNemar** | тест для pass/fail на одних и тех же кейсах. Для баллов тест другой, и evalstat выбирает сам |
| **not distinguishable** | это не «одинаково». Это «этот набор слишком мал, чтобы различить» |
| **anytime interval** | более широкий диапазон, который остаётся честным, если смотреть на метрику снова и снова |
| **shrinkage factor** | насколько неидеальный оценщик сплющивает настоящие различия |
| **adjusted** | p-value после учёта того, сколько метрик проверялось одновременно |

## Любой инструмент, через таблицу

Не promptfoo? Выгрузи таблицу из трёх колонок — какой кейс, какой вариант, что
получилось — в CSV или JSON lines:

```
case,variant,value
q1,baseline,pass
q1,candidate,pass
q2,baseline,fail
q2,candidate,pass
```

```bash
evalstat compare runs.csv
```

Значения могут быть `pass`/`fail`, `1`/`0` или любым числом. Имена колонок
задаются через `--case-column`, `--variant-column` и `--value-column`. Базовым
считается вариант, который встретился в файле первым, либо укажи его явно через
`--a` и `--b`.

## Несколько метрик сразу

```bash
evalstat compare results.json --metric all
```

```
  metric           difference         p   adjusted  verdict
  success            +14.0 pp     0.016      0.062  undecided
  helpfulness        +14.0 pp     0.016      0.062  undecided
  tone                +9.5 pp     0.077      0.077  undecided
```

Каждая метрика по отдельности выглядит значимой. Проверка четырёх даёт четыре
шанса ошибиться, и после поправки не выживает ничего.

## Зачем это нужно

У `promptfoo`, `deepeval` и `ragas` вместе около 63 000 звёзд на GitHub и ни одного
вхождения `mcnemar` или `paired bootstrap` в исходниках. Они показывают два средних
по колонкам, а сравнение оставляют читателю.

При этом всё нужное уже лежит в файле выгрузки. Прогон promptfoo, сравнивающий два
промпта, записывает каждую ячейку (тест-кейс, вариант) с ключами `testIdx` и
`promptIdx` — то есть парный дизайн, сохранённый на диск и затем усреднённый.

Обоснование каждого числа — в [docs/method.ru.md](docs/method.ru.md).

## Чего он пока не делает

- **Нативно читается только формат promptfoo**, всё остальное — через таблицу выше.
- **Парсер не видел живого прогона.** Он проверен на фикстурах, построенных по
  опубликованным интерфейсам promptfoo `EvaluateResult` и `OutputFile`, но не на
  файле, который записал настоящий `promptfoo eval`.
- **Никаких причинных утверждений.** Если ты сам выбирал, какие кейсы перезапустить,
  никакая статистика здесь это не исправит.

## Проверки

140 тестов, без сети и без API-ключа. Табличные квантили хи-квадрат и нормального
распределения воспроизведены до девятого знака; точный биномиальный тест сверен с
посчитанными руками хвостами и независимо — с 40 000 симулированных подбрасываний
монеты; поправка Холма сверена с `p.adjust` из R. Утверждения измеряются, а не
объявляются: формула размера выборки проверяется прогоном (считаем `n`, прогоняем
столько раз, сверяем обещанную мощность), а коэффициент сплющивания — симуляцией
судьи с известной ошибкой, через которого известная разница сжимается ровно на него.

```bash
pip install -e ".[dev]"
pytest
```
