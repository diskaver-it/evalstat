# evalstat

[![CI](https://github.com/diskaver-it/evalstat/actions/workflows/ci.yml/badge.svg)](https://github.com/diskaver-it/evalstat/actions/workflows/ci.yml)

*[English version](README.md)*

Дашборд евалов показывает: новый промпт 68% против 62% у старого. Шесть пунктов.
Мержим.

```
$ evalstat compare examples/demo_run.json

success on 50 paired test cases

  baseline prompt  0.620
  new prompt       0.680
  difference       +6.0 pp   95% CI [-8.0 pp, +18.0 pp]
  test             McNemar, exact, p = 0.549   (7 gained, 4 lost, 39 tied)

  VERDICT: new prompt is not distinguishable from baseline prompt

  - 39 of 50 pairs agreed in both variants and carry no information about the difference.
  - Undecided is not the same as equal: an effect smaller than 13.0 pp would not have been visible at this sample size.
```

Новый промпт починил семь кейсов и сломал четыре. Это подбрасывание монеты, и
никакой eval-набор из пятидесяти примеров не мог бы сказать иначе: минимальная
разница, которую этот прогон вообще был способен увидеть, — тринадцать пунктов.

А каким тогда должен быть набор?

```
$ evalstat plan examples/demo_run.json --detect 0.03

plan for success, from 50 paired test cases

  the variants disagreed on              11 of 50 pairs (22.0%)
  smallest effect these pairs can see    +18.1 pp
  to see +3.0 pp you need                1 917 paired test cases

  at 80% power, alpha 0.05
```

Допущение под этим числом не выдумано: прогон, который уже есть, говорит, как часто
два варианта реально расходятся, а для парного теста именно эта доля определяет
мощность.

Воспроизвести блок выше, без API-ключа и без сети:

```bash
python examples/make_demo.py
evalstat compare examples/demo_run.json
```

## Зачем это нужно

У `promptfoo`, `deepeval` и `ragas` вместе около 63 000 звёзд на GitHub и ни одного
вхождения `mcnemar` или `paired bootstrap` в исходниках. Они показывают два средних
по колонкам, а сравнение оставляют читателю.

При этом всё нужное уже лежит в файле выгрузки. Прогон promptfoo, сравнивающий два
промпта, записывает каждую ячейку (тест-кейс, вариант) с ключами `testIdx` и
`promptIdx` — то есть парный дизайн, сохранённый на диск и затем усреднённый.

## Установка и использование

```bash
pip install evalstat
```

```bash
# два промпта или два провайдера внутри одного прогона
promptfoo eval --output results.json
evalstat compare results.json

# прогон «до» и «после»
evalstat compare before.json after.json

# какие варианты лежат в файле?
evalstat arms results.json

# гейт для пулл-реквеста: exit 1 при значимой регрессии
evalstat compare results.json --fail-on regression

# сколько кейсов нужно, чтобы увидеть сдвиг в три пункта?
evalstat plan results.json --detect 0.03

# на метрику смотрят после каждого коммита — значит и судить надо так
evalstat compare results.json --anytime --fail-on regression
```

Опции, которые стоит знать: `--metric success|score|<имя метрики>`,
`--by prompt|provider`, `--a` / `--b` — выбор варианта по индексу или подписи,
`--alpha`, `--format text|markdown|json`, `--fail-on none|regression|any`. Формат
`markdown` рассчитан на вставку в пулл-реквест, `json` — на то, что читает дальше.

## Внутри CI пять процентов — это не пять процентов

Гейт смотрит на метрику не один раз. Он смотрит после каждого коммита, а доля
ошибок даётся на один взгляд. Измерено на верной нулевой гипотезе при двенадцати
взглядах:

| | находит разницу, которой нет |
| --- | --- |
| фиксированный интервал, один взгляд в конце | 6.0% |
| фиксированный интервал, все двенадцать взглядов | **26.5%** |
| anytime-интервал, все двенадцать взглядов | 1.0% |

`--anytime` заменяет фиксированный интервал доверительной последовательностью,
которая верна одновременно при любом размере выборки. Не нужно объявлять число
взглядов заранее и не нужно распределять между ними alpha — а это важно, потому что
никто не знает, сколько коммитов займёт ветка. На демо это стоит множителя 2.4 по
ширине:

```
watched continuously, alpha 0.05

  difference           +6.0 pp
  anytime interval     [-22.3 pp, +34.3 pp]
  fixed interval       [-6.0 pp, +18.0 pp]   2.4 times narrower

  VERDICT: not established under repeated looks
```

Граница адаптируется к увиденной дисперсии, а вес каждого кейса считается только по
предыдущим кейсам. Это ограничение и есть причина, по которой гарантия сохраняется:
оценка дисперсии, подсмотревшая значение, которое ей сейчас взвешивать, её бы
обнулила.

## Пять решений, на которых держатся числа

**Парность — это и есть весь выигрыш, а не уточнение.** Два прогона по одному
eval-набору различаются отчасти потому, что различаются промпты, а отчасти потому,
что часть тест-кейсов просто сложнее. Сравнение средних по колонкам оставляет вторую
часть внутри шума; разность внутри тест-кейса её убирает. По этой же причине в отчёт
выводятся совпавшие пары: 39 из 50 кейсов повели себя одинаково в обоих вариантах и
вообще ничего не говорят о том, какой промпт лучше — вот так прилично выглядящий
набор оказывается неспособен различить шесть пунктов.

**Тест и интервал — намеренно разные процедуры.** Тест значимости имеет право
предполагать нулевую гипотезу; доверительный интервал — нет, потому что нулевая
гипотеза и есть то, что он измеряет. Поэтому p-value считается процедурой, построенной
на нуле (точный McNemar по дискордантным парам либо парная перестановка со сменой
знаков для непрерывных баллов), а интервал — бутстрапом пар как они наблюдались. Если
они расходятся, а около порога это бывает, отчёт так и говорит, а не выбирает тот
ответ, который приятнее.

**Повторы — это не дополнительные наблюдения.** Если `repeat` прогнал каждый
тест-кейс три раза, в файле три строки на ячейку. Считать их независимыми — значит
раздуть `n` и сузить интервал ни на чём. Они усредняются в одно число на ячейку, а
pass/fail при этом превращается в долю — поэтому тест дальше переключается с McNemar
на перестановочный.

**Тест-кейсы сопоставляются по `vars`, а не по порядку строк.** Порядок работает внутри
одного прогона и молча врёт между двумя прогонами, если набор за это время изменился.
Если в файле нет `vars`, по которым можно сопоставить, отчёт сообщает, что пришлось
откатиться к позиции.

**Мощность даёт доля расхождений, а не размер eval-набора.** Поэтому `plan` спрашивает
про эту долю уже прошедший прогон, а не просит тебя угадать. Два варианта, которые
почти во всём совпадают, могут потребовать тысячи кейсов, чтобы их развести, — а
набор, который на пятидесяти примерах выглядит щедрым, не различает ничего мельче
восемнадцати пунктов.

Зависимостей нет — только стандартная библиотека, включая хвост хи-квадрат, точный
биномиальный тест и обратную функцию нормального распределения. Гейт для евалов должен устанавливаться и отрабатывать в чужом CI за
секунды, а дерево зависимостей — обычная причина, по которой такую проверку так и не
внедряют.

## Чего он пока не делает

- **Нет поправки на несколько метрик.** Проверять восемь named scores сразу — значит
  раздувать долю ложных срабатываний; пока метрику надо выбрать до прогона.
- **Нет калибровки судьи.** Если ответы оценивает LLM, её согласие с человеком — это
  отдельная задача измерения, и здесь она не решается.
- **Читается только формат выгрузки promptfoo.**

## Проверки

99 тестов, без сети и без API-ключа: табличные квантили хи-квадрат и нормального
распределения воспроизведены до девятого знака, точный биномиальный тест сверен с
посчитанными руками хвостами и независимо — с 40 000 симулированных подбрасываний
монеты, доли ложных срабатываний обоих тестов измерены симуляцией при верной нулевой
гипотезе, покрытие бутстрап-интервала измерено на 200 синтетических экспериментах.
Ни одно из двух главных утверждений не принято на веру. Формула размера выборки
проверяется так: считаем по ней `n`, прогоняем сравнение столько раз и смотрим, что
обещанная мощность и есть полученная. Таблица выше — это тест, который подглядывает
двенадцать раз при верной нулевой гипотезе и падает, если последовательность
сломается или если фиксированный интервал, наоборот, не сломается.

Честное ограничение: парсер проверен на фикстурах, построенных по опубликованным
интерфейсам promptfoo `EvaluateResult` / `OutputFile`, но пока не на файле, который
записал живой прогон `promptfoo eval`.

```bash
pip install -e ".[dev]"
pytest
```
